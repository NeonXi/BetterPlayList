# BetterPlayList v5.0

网易云音乐智能随机播放工具 —— 打破官方"伪随机"的局限，让歌单真正随机起来，并把结果**静默写入网易云播放队列**（不抢焦点、不弹窗）。

> 名词速览
> - **播放队列**：网易云底部「播放队列」面板里那一排"接下来要播的歌"。
> - **静默**：操作网易云时不把它的窗口弹到最前、不打断你当前正在用的窗口。
> - **PID**：每个 Windows 进程的唯一编号。
> - **命名管道（Named Pipe）**：Windows 上同一台电脑里两个程序之间收发文本的一种内部通道，路径形如 `\\.\pipe\名字`，不走网络。
> - **DLL 注入**：让一个正在运行的程序（这里指网易云）额外加载一个 DLL 模块，从而在它进程内部执行指令。
> - **CEF**：Chromium Embedded Framework，网易云界面就是用它套的网页内核。

## 为什么做这个工具？

网易云 PC 客户端自带的"随机播放"存在以下问题：

- **随机不彻底**：经常连续播放同一歌手、同一专辑的歌曲
- **热门歌循环**：冷门歌曲几乎不会被随机到
- **无记忆功能**：每次随机结果雷同，近期听过的歌反复出现

BetterPlayList 通过**自定义随机算法 + 静默队列写入**解决这些问题，让你听到真正"随机"的歌单。

## 功能特性

### 🎲 两种随机算法

| 算法 | 说明 |
|------|------|
| **SuperShuffle 强力洗牌** | Fisher-Yates 公平洗牌 + 近期播放去重，近期听过的歌自动后置 |
| **Configurable 可配置分散随机** | 在公平洗牌基础上，额外确保相邻歌曲在**热度 / 歌手 / 年代**三个维度上分散，避免连续听到相似歌曲 |

### 🔇 静默写入播放队列（核心亮点）

- **全自动，无按钮**：检测到网易云运行后，程序会**自动注入桥接 DLL 并建立内部通道**，整个过程约 0.5 秒，用户无感知
- **进程内直连**：指令在网易云进程内部通过 CEF 执行，写入时**完全不唤起窗口、不抢焦点**
- **FIFO 正序写入**：按随机结果的顺序逐首 `ADD_NEXT`，先写的先播，最终播放顺序与预览一致
- **失败重试**：单首写入失败后等待 150ms 自动重试一次
- **边清边播**：勾选"插入前清空播放队列"时，先真正清空队列、第一首立即播放，其余歌曲继续静默写入

### 🧹 清空播放队列

- 勾选"插入前清空播放队列"后，会通过网易云官方的 **orpheus:// 协议**真正清空当前队列
- ⚠️ **清空这一瞬间会短暂拉起网易云主窗口**（约半秒，属正常现象，界面勾选框旁也有标注）；除此之外的逐首插入全程静默
- 清空后自动轮询确认队列确实为 0，再开始写入

### 🎵 歌单管理

- 本地 Cookie 自动登录（无需手动输入账号密码）
- 歌单列表搜索、预览
- 歌单 JSON 缓存，二次加载秒开（缓存命中时不请求网络）
- 支持手动输入分享链接 / 歌单 ID
- **支持超大歌单**（突破 1000 首限制，实测 3800+ 首完整加载）
- 加载时按钮动态显示"加载中..."，避免误以为卡顿

### 👁️ 实时预览

- 选中歌单后实时展示随机处理结果
- 切换算法、调整参数时**实时重新排列**
- 预览列：序号、歌名、热度、歌手、年代、听过次数
- **流式加载**：大歌单加载过程中实时刷新列表，边下边看
- 双击歌曲直接添加到"下一首播放"

### 📝 播放历史

- 记录每次写入的歌曲 ID
- 近期去重窗口可调（0-100 首），避免短时间内重复听到同一首歌

## 核心技术实现：静默写入是怎么做到的？

这是本项目最关键的部分。整体分三步走：**定位网易云 → 注入桥接 DLL → 命名管道发指令**。

### 第一步：定位网易云主播放窗口

网易云启动后通常有**多个 `cloudmusic.exe` 进程**（主进程 + 渲染/GPU 辅助进程）。程序通过任务列表枚举所有 PID，再用 `EnumWindows` 逐进程查找类名为 **`OrpheusBrowserHost`** 的窗口，挑选尺寸 ≥ 400×300 的大窗口（最小化但有标题的窗口作为备选），从而锁定真正承载播放界面的那个进程。

### 第二步：自动注入桥接 DLL

程序先尝试连接命名管道发送 `HELLO`：

- **能连上**：说明桥接 DLL 已在网易云里（可能是本次已注入，或用户装了嗷呜点歌机），直接进入下一步。
- **连不上**：自动执行注入，无需用户点任何按钮。

注入流程（对齐官方做法）：

```
OpenProcess（仅申请最小权限：CREATE_THREAD | VM_OPERATION | VM_READ | VM_WRITE | QUERY_INFORMATION）
    ↓
VirtualAllocEx（PAGE_READWRITE 普通内存页，非可执行页，减少被杀软拦截）
    ↓
WriteProcessMemory（把 DLL 的完整路径以 UTF-16 编码写进网易云进程）
    ↓
解析目标进程里的 LoadLibraryW 地址（见下方说明）
    ↓
CreateRemoteThread（在网易云里开一个线程调用 LoadLibraryW 加载 DLL）
    ↓
WaitForSingleObject 等待加载完成
    ↓
轮询 HELLO，最长 12 秒等待桥接返回 READY
```

**为什么要"解析" LoadLibraryW，而不直接用地址？**
`LoadLibraryW` 在不同 Windows 版本里可能由 `kernel32.dll` 转发到 `kernelbase.dll`。程序先在自己进程里确认该函数**真正所属的模块**，算出"函数地址 − 模块基址"的偏移；再用 Toolhelp 快照找到网易云进程里**同名模块的基址**，加上同样的偏移，得到正确的远程函数地址。这样不依赖两边加载地址是否一致。

> **64 位安全**：所有句柄、地址参数都显式声明了 64 位函数签名，避免地址被截断。

### 第三步：命名管道发指令（真正的插入动作）

桥接 DLL 加载后，会在网易云进程内创建命令命名管道：

```
\\.\pipe\AwooNcmCefBridge-v1-{网易云PID}
```

通信规则：

| 项目 | 说明 |
|------|------|
| **协议** | 纯文本，命令 + `\n` 结尾，读取一行响应 |
| **连接方式** | 每条命令建立一次连接、读完响应即关闭 |
| **握手** | `HELLO 1` → 成功返回 `OK READY ... profile=netease-3.1.41 ...` |
| **插入** | `ADD_NEXT {歌曲ID}` → 成功返回 `OK POSTED` |
| **立即播放** | `PLAY {歌曲ID}` → 成功返回 `OK POSTED` |
| **响应约定** | 以 `OK` 开头表示成功，以 `ERR` 开头表示失败 |

**为什么这样能静默？** 指令由桥接 DLL 在网易云进程**内部**直接交给 CEF 处理，等价于在它自己的网页内核里点了"下一首播放"，不需要把窗口显示或激活，因此全程不抢焦点、不弹窗。

**顺序如何保证？** 连续 `ADD_NEXT` 的"下一首"队列按 **FIFO（先进先出）**排列。所以程序按随机结果**正序**逐首写入即可。实测正序写入 [A, B, C] 后，通过网易云内部状态逐级确认播放链为 **A → B → C**（本地队列文件里的 `randomOrder` 字段只是加入时分配的随机数，并不代表插入队列顺序，验证以实时"下一首"为准）。

### 清空队列：orpheus:// 协议

桥接 DLL **没有提供"清空"命令**（实测 `CLEAR` 等均返回"未知命令"）。因此清空走网易云官方注册的 **orpheus://** URL Scheme：

```
把 {"cmd":"playingList","type":"clear"} 做 JSON + base64 编码
    ↓
拼成 orpheus://{编码}
    ↓
ShellExecuteW(None, "open", url, ..., SW_HIDE)
```

已实测：队列有 3 首时发送，队列真实变为 0 首。`SW_HIDE` 参数尽量隐藏窗口，但**清空这一下网易云仍可能短暂拉起主窗口**，这是该协议的固有行为，故在界面明确标注。

### 其他：超大歌单流式加载

网易云 `/api/v3/playlist/detail` 返回的 `trackIds` 上限为 1000 个。超过 1000 首时，自动通过分页接口 `/api/playlist/track/all` 补取剩余 ID，再分批拉取歌曲详情。每获取约 200 首就回调 UI 实时追加，做到边下边看。

### 本地 Cookie 自动登录

网易云 PC 客户端把登录 Cookie 加密存在本地 SQLite 中，程序按以下链路自动读取，全程无需输入账号密码：

```
Chrome DPAPI 解密 → AES-GCM 解密 → 提取 MUSIC_U 等关键 Cookie
```

## 使用说明

### 环境要求

- Windows 10 / 11（64 位）
- 网易云音乐 PC 客户端（已登录），适配版本 **3.1.41.205529**
- 无需安装嗷呜点歌机 / AwooMusicBot，桥接 DLL 已随程序打包

### 运行方式

**方式一：直接运行 exe（推荐）**

下载 Release 中的 `BetterPlayList_v5.0.exe`，双击运行。

**方式二：Python 源码运行**

```bash
pip install -r requirements.txt
python main.py
```

**方式三：自行打包**

```bash
python build.py
# 生成 dist/BetterPlayList_v5.0.exe
```

### 操作步骤

1. 先打开网易云音乐并登录
2. 启动 BetterPlayList，程序自动读取本地 Cookie 登录
3. 点击"**加载我的歌单**"或输入分享链接 / 歌单 ID
4. 等待加载完成（按钮显示"加载中..."）
5. 选择随机算法、调整参数；如需清空当前队列可勾选"**插入前清空播放队列**"
6. 点击"写入播放队列"——程序会自动完成注入与写入，无需任何手动注入操作
7. 回到网易云，队列已按随机结果更新；勾选清空时第一首会立即响起

## 常见问题

### Q: 网易云必须先运行吗？

是的。注入需要目标进程已在内存中才能 `OpenProcess` → `CreateRemoteThread`。若网易云未运行，程序会提示"没有发现正在运行的网易云音乐"，启动网易云后再点写入即可。

### Q: 需要手动点"注入"吗？

不需要。v5.0 已移除注入按钮，点"写入播放队列"时程序会在约 0.5 秒内自动完成注入并写入。

### Q: 网易云关闭后重新打开，还要重新注入吗？

会自动处理。网易云重启后进程是全新的、不含桥接 DLL，下次点写入时程序检测到通道未连接，会自动重新注入。

### Q: 写入时提示"权限不足 / ACCESS_DENIED"怎么办？

这通常是因为**网易云以管理员身份运行**，而本程序是普通权限，跨权限级别无法打开它的进程。请用**管理员身份运行 BetterPlayList**（右键 exe → 以管理员身份运行）后重试；或用普通权限重启网易云。

| 原因 | 解决办法 |
|------|----------|
| 网易云是管理员权限运行 | 以管理员身份运行 BetterPlayList |
| 网易云是 32 位 | 请使用 64 位版本 |
| 安全软件拦截 | 将程序加入信任名单 |
| 检测到旧桥接残留 | 完全退出并重新打开网易云 |

### Q: 为什么清空时网易云窗口会闪一下？

清空走的是网易云官方 `orpheus://` 协议，该协议被唤起时会短暂激活主窗口（约半秒），这是协议固有行为。逐首插入则完全静默。

### Q: 打包成单文件 exe 后，缓存文件在哪？

exe 运行时会在 **exe 同目录**创建 `data/` 文件夹（`history.json`、`playlists/` 缓存）。桥接 DLL 打包在 exe 内部、启动时自动解压，`data/` 是外部文件夹、不会被打进 exe。
